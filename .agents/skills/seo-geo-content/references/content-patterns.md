# Content patterns by intent

Read this reference when choosing a page shape, planning a content set, or
restructuring more than a small passage. Select the smallest pattern that
resolves the reader's task. These are editorial options, not ranking formulas.

## Pattern selection

| Reader intent | Useful shape | Essential content |
|---|---|---|
| Understand a concept | Definition or explainer | Direct definition, mechanism, boundaries, concrete example |
| Solve a problem | Guide or tutorial | Prerequisites, ordered actions, observable result, failure boundaries |
| Evaluate options | Comparison or alternatives page | Decision criteria, honest differences, best-fit cases, current sources |
| Assess an offering | Product or service page | User need, actual offering, supported conditions, limitations, next action |
| Explore a scenario | Use-case page | Situation, inputs, decisions, actions, components, realistic boundary |
| Verify proof | Project story or case study | Evidence, attribution, deployment status, measured result or explicit absence |
| Resolve a focused objection | FAQ | Direct answer, necessary qualification, canonical next resource |
| Implement something | Documentation | Goal, prerequisites, commands or steps, expected output, troubleshooting |

Do not create a separate page merely because a keyword variant exists. Give a
topic its own page only when it owns a distinct user task, evidence, and useful
contribution.

## Build a coherent answer

The opening should name the subject, resolve the primary question or establish
the concrete situation, and include any condition whose omission would
mislead. Continue with only the context the reader needs to decide or act.

- Give each section one job and a heading that describes it naturally.
- Keep facts that depend on each other together.
- Use ordered steps when sequence matters and tables when readers must compare
  the same attributes; explain consequences in prose.
- Use FAQs for focused objections or questions that do not deserve a separate
  canonical page.

Avoid generic scene-setting, unsupported superlatives, repeated category
phrases, and fragments created solely for machines. The page must remain
coherent from beginning to end.

## Comparisons

Define decision criteria before declaring a best fit. Verify both products from
current primary sources, acknowledge meaningful competitor strengths, and say
who each option is suited to. Separate factual differences from the business's
positioning.

Do not infer that publishing a comparison will make an assistant recommend
the publishing business. The page may instead become a source used to describe or recommend the
competitors it names.

## Demonstrate rather than decorate

Use examples and relevant images, diagrams, or video when they clarify a
mechanism, decision, or result. They support the answer; they do not prove a
universal capability, and essential claims must not live only in media.

## Complete the page

The title, description, H1, opening, and CTA should express one purpose without
forcing identical wording. Link contextually to the next question with
descriptive anchor text, and connect educational content to the offering without
turning every paragraph into a sales pitch.

Treat character counts and keyword placement as interface or query
considerations, not universal formulas. Review affected locales as natural,
publishable pages that preserve the same facts, limitations, intent, and CTA
destination.

## Content-set planning

When several pages are proposed, map:

- the user task owned by each page;
- its primary evidence;
- its relationship to product, FAQ, project, or documentation owners;
- parent, sibling, and next-step internal links; and
- overlap that should be consolidated rather than published.

Prioritize pages by audience value, product relevance, available evidence, and
measured demand. Search volume alone does not establish content value, and an
agent-generated list of topics is not keyword research.
